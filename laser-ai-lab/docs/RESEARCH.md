# 探索アルゴリズムの比較実験

## 問いを決める

本アプリの初期比較は「同じ盤面分布で、ランダムAIと短期的な獲得を狙うAIにどれだけ成績差があるか」です。AI02を最強とする研究ではありません。AI03以降でMinimax、αβ枝刈り、単純モンテカルロ、MCTSなどを追加し、性能と計算資源の関係を比較できます。

アルゴリズム以外の違いも同時に変えると効果を分離しにくくなります。評価関数・乱数条件・制限をそろえた対照実験を別に設けてください。Minimaxとαβ探索は、同じ評価関数・探索深度・同点処理なら同じ最適値を返すべきです。固定深度の正しさ比較と、固定計算資源の強さ比較を分けます。

## 実装されている実験プロトコル

1. 実験シードから重複しない盤面シードを生成します。
2. 同じ盤面をすべてのAIの組合せで使います。
3. AI A先手・B後手、B先手・A後手の2局を1ペアとして実行します。
4. 実行順序も盤面・組合せごとに交替させます。
5. 各AIを事前に3回呼び出してから計時します。ただし、これでブラウザの最適化や負荷の影響を完全に除去できるわけではありません。
6. 同時に複数の対局を走らせず、1つのWorker内で直列に計算します。
7. 完了した先後ペアを逐次UIに送信します。停止時には未完了ペアを捨てます。

ゲームの途中の乱数シードは、実験シード、盤面シード、AIの組合せ、AI ID、手番、手数から決まります。AI01・AI02は壁時計による打切りを使わず、固定シミュレーション予算なので、同じ条件で手順を再現できます。計時値は再現されるとは限りません。

## 得点率と勝率

本アプリの主要指標は **得点率** です。

```text
勝ち = 1、引き分け = 0.5、負け = 0
得点率 = (勝ち数 + 0.5 × 引き分け数) / 対局数
```

これを純粋な勝率と混同しないでください。勝・分・敗を別に表示します。共有コアの獲得数と対局勝敗は別の量で、平均獲得コア数も併記しています。

総合ランキングは参加AIに依存します。ゲームに相性の循環がある場合、1本の順位だけで優劣を表せません。直接対戦の表と、異なる対戦相手への結果を重視してください。

## 信頼区間の設計

同じ盤面の先後2局は独立な標本ではありません。そこで、AI Aから見た2局の得点の平均を、その盤面の値 X_i とします。

```text
0 <= X_i <= 1
estimate = mean(X_i), i = 1 ... n
```

nは**盤面ペア数**であり、対局数ではありません。

独立な盤面標本と固定した評価対象AIを仮定し、Hoeffdingの不等式から

```text
P(|estimate - expectation| >= epsilon) <= 2 exp(-2 n epsilon^2)
```

を使用します。比較の組合せ数をM、全体の有意水準をalpha = 0.05とし、Bonferroni補正で

```text
epsilon = sqrt(log(2 M / alpha) / (2 n))
interval = [max(0, estimate - epsilon), min(1, estimate + epsilon)]
```

とします。この方法は正規近似を使わず、かなり保守的です。実際の標本分散が小さい場合にも幅が広くなるため、「差があるのに判定しにくい」ことがあります。一方で、先後2局を別標本として数えることによる過剰な確信を避けます。

AI Aの区間の下限が50%を超えた場合、その比較条件におけるAの優位を支持する表示になります。上限が50%未満ならBを支持し、50%を含む場合は優位と判定しません。「差がないことを証明した」という意味ではありません。

この式はプロジェクト内に直接実装しており、外部統計ライブラリには依存しません。

## 適用範囲と重要な限界

- 盤面は疑似乱数シードで生成し、到達可能性検証に通ったものだけを採用します。評価対象はこの生成器の採用分布です。全レーザーゲーム・全初期配置への一般化ではありません。
- 盤面を独立標本とみなすモデルに基づきます。シードに決定論的な疑似乱数を使うこと自体が、数学的な独立性の証明ではありません。
- 最初に決めた盤面数を完了した結果で判断してください。途中で区間を見て、勝っているところで停止する判断には同じ95%保証はありません。途中・停止・エラー時の結果は探索的な参考値として表示します。
- AIを結果に合わせて何度も修正した後、同じ盤面群で最終評価すると過適合します。調整用シードと未使用の最終評価用シードを分けてください。
- 複数の実験をやり直して都合の良いものだけ選ぶ行為は、ここでの多重比較補正の対象に含まれません。
- 1手の「シミュレーション上限」は固定時間ではありません。AI01は探索せず、AI02は経路グラフの処理も行うため、同じ上限でも計算内容が異なります。
- 高速なAIの時間表示が0.00 msになる場合は、計時分解能と丸めの影響です。計算が本当にゼロ時間という意味ではありません。

## 記録されるもの

実験JSONには、エンジン版、生成器版、WasmバイナリのSHA-256、各AIのID・版、実験シード、予算、予定盤面数、開始日時、実行ブラウザ、各対局の初期シード、全操作・個別乱数シード・計算量・思考時間・得点を保存します。

CSVは対局単位の確認用です。完全な研究記録にはJSONを併せて保存し、使用ソースのGitコミットID、OS、CPU、ブラウザ版、電源モードも別に記録してください。WasmのハッシュはJavaScriptの自作AIの変更を検出しません。

## 研究の進め方の一例

まずAI01を下限の基準、AI02を単純な戦術基準として固定します。AI03を追加したら、調整用盤面で実装の問題を見つけ、未使用シードでAI01・AI02・AI03の総当たりを行います。勝敗だけでなく、予算ごとの成績・中央値と遅い局面の思考時間・獲得コア数を比較します。

AIが負けた局面を棋譜で再生し、「即時獲得の見逃し」「相手に1手で渡す」「進展のない反復」などに分類すると、次の改善点を説明しやすくなります。
