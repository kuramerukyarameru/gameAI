# LASER / AI LAB — AI01〜AI25 実装ガイド

この資料は、同梱されたC++実装の説明です。25体が25種類の独立した探索原理という意味ではありません。
αβ、Negamax、反復深化、置換表は関連する方法で、同じ実装の構成要素を変えた比較を含みます。
強さの順位は未決定です。名称や番号は性能ランキングではありません。

## 共通ルールと公平な比較

15×15マス、鏡6〜200枚、共通レーザー3台、共通コア3個。1操作で鏡1枚を90°回転すると3台が同時発射し、当たった未獲得コアを操作側が獲得します。
コアは同一発射中は光を止め、次の操作から透明になります。同じコアへの重複命中は1得点です。
30操作、または3個のコアがすべて獲得された時点で終了します。残りコアがなくなった後の操作を省略しても最終得点は変わりません。
光路が循環する場合は、マスと進行方向の再訪を検出してその光線を終了します。

探索は共通のゲームエンジンを使い、現在の盤面だけを見ます。生成時の解答手順はAIに渡しません。
鏡の番号は毎回シャッフルされ、コアの近くの鏡などが固定番号で分かる設計ではありません。
シード・枚数・ルール版・AI版・WasmのSHA-256・予算を記録します。

固定ノード予算と固定時間予算は別の実験です。ノードはシミュレーション中の合法な1操作の適用回数です。
評価関数呼び出し、光路計算、BFS訪問数は別に記録するため、同じノード数は同じCPU費用を意味しません。
時間上限は協調的なチェックで、厳密なハードリアルタイムではありません。1処理ぶん超過する場合があります。
未使用の予算を消費するためだけの計算は行いません。

共通の手作り評価は、獲得コア差を主にし、光路とコアの距離を補助に使います。
これは「コアまでの真の最短回転手数」ではありません。
終局では勝ち・引き分け・負けを正確に評価します。モンテカルロ系の勝敗得点は1・0.5・0です。

## AI01 — Random（ランダム）

合法な鏡から、均等な確率で1枚を選びます。研究の最小基準です。

### 動作手順

1. 現在の鏡の枚数を取得する。
2. シード付き乱数で0〜枚数−1の整数を選ぶ。
3. その番号の鏡を90°回転する。

**評価・選択の式：** `P(a) = 1 / 鏡の枚数`

**狙い：** 計算がほぼ不要。探索による改善を測る出発点になります。

**限界：** 盤面やコアを見ません。弱い相手に勝っただけでは強いAIの証明になりません。

**比較の観点：** AI02・AI07と比較して、経路計画や1手評価だけの効果を調べます。

**パラメータ：** 探索局面数は0。乱数シードが同じなら同じ手を返します。

**実装：** `cpp/algorithms.hpp` の `randomAI()`。

## AI02 — Rush Planner（経路計画）

コアに届く鏡の向きを計画し、即時得点と相手の反撃も考慮して早い獲得を狙います。

### 動作手順

1. 0–1 BFSで、各コアまでの回転数が少ない反射経路候補を探す。
2. 同じ鏡に矛盾する向きを要求する経路は棄却し、残った操作列を実際のエンジンで検証する。
3. 各初手の得点・相手の1手獲得・計画との差分を評価する。
4. 最高評価の鏡を選ぶ。

**評価・選択の式：** `獲得差 × 100 + 即時得点 × 30 − 反撃 × 110 − 経路との差分`

**狙い：** ランダム試行で偶然コアを発見するのを待たず、目標に向かう候補を作れます。

**限界：** 最速勝利を証明するAIではありません。BFSは緩和された経路モデルで、見つからない場合もあります。少ない予算では反撃の確認が部分的です。

**比較の観点：** AI07との比較は経路知識の効果、AI18との比較は攻撃と防御の違いを表します。

**パラメータ：** 盤面遷移とBFS訪問数を別々に記録。反撃試行は残り予算を初手に配分します。

**実装：** `cpp/algorithms.hpp` の `rushAI()`。

## AI03 — Flat Monte Carlo（単純モンテカルロ）

初手ごとに、両者がランダムに動いた場合の終局を何度も試します。

### 動作手順

1. 初手の候補順をシード付きでシャッフルする。
2. 候補を1つ適用し、その後は両者ともランダムに終局まで進める。
3. 勝ち1・引き分け0.5・負け0を初手ごとに平均する。
4. 試行を候補へ巡回配分し、平均が最大の手を選ぶ。

**評価・選択の式：** `Q(a) = (勝ち数 + 0.5 × 引き分け数) / 完了した試行数`

**狙い：** 評価関数を設計せず、実際の終局結果を使えます。

**限界：** 推定するのはランダムな続きに対する成績であり、最善応手への勝率ではありません。予算が少ないと未試行の初手が残ります。途中で切れた試行は集計しません。

**比較の観点：** AI06・AI15との比較で、木の再利用と試行配分の効果を検証できます。

**パラメータ：** 各候補に同じ回数を事前保証するのではなく巡回配分。最低予算では全候補を試せない場合があります。

**実装：** `cpp/algorithms.hpp` の `monteCarloAI()`。

## AI04 — Beam Minimax（ビーム型選択探索）

各局面で有望な手を幅kまで残し、相手も自分にとって有利な手を選ぶと仮定して先読みします。

### 動作手順

1. 各合法手を1手評価する。
2. 手番側から見て評価の高いk手だけを残す。
3. 残した手を交互の最大化・最小化で探索する。
4. 深さを増やし、根の候補をすべて評価できた最後の結果を採用する。

**評価・選択の式：** `V(s) = max / min { V(s′) | s′ ∈ 上位k子局面 }`

**狙い：** 分岐の大きな盤面でも、全幅探索より先に進める可能性があります。

**限界：** 実装は各ノードの子を絞るBeam-Minimaxです。深さごとの全局面を一括選抜する古典的な大域ビーム探索とは異なります。捨てた手に最善手がある可能性があります。

**比較の観点：** AI05と比べて候補削減の速度と見落としを測定。幅を鏡の枚数まで増やす比較も有効です。

**パラメータ：** 共通の幅・深さ設定を使用。深さ1の評価を初期の代替手として保持します。

**実装：** `cpp/algorithms.hpp` の `beamAI()`。

## AI05 — Alpha-Beta（αβ枝刈り）

全合法手を候補とするMinimaxに、結論を変えない枝を省くαβ枝刈りを適用します。

### 動作手順

1. まず1手評価で代替手を用意する。
2. 設定した深さに向けて、交互の最大化・最小化を探索する。
3. αとβの境界から、結果を変えない枝を打ち切る。
4. 指定深さを根全体で完了した場合だけ、その結果を採用する。

**評価・選択の式：** `α ≥ β になった枝を打ち切る`

**狙い：** 探索が完了すれば、同じ深さ・評価関数のMinimax値を保ったまま計算を減らせます。

**限界：** 30手先の完全解を求めるものではありません。予算内に指定深さを完了できなければ1手評価へ戻ります。

**比較の観点：** AI14と同じ深さ・十分な予算で比較すると枝刈りの効果を分離できます。AI08との差は反復深化です。

**パラメータ：** 深さ・ノード上限・時間上限を使用。未完了の深い探索を、完了した最適解として表示しません。

**実装：** `cpp/algorithms.hpp` の `alphaBetaAI()`。

## AI06 — Epsilon MCTS（ε-greedy木探索）

探索した枝の成績を木に保存し、80%は平均成績、20%はランダムな枝で探索します。

### 動作手順

1. 未展開の手を1つ展開する。
2. 既存の枝ではε=0.2で探索し、残りは手番側に有利な平均値を利用する。
3. その先をランダムに終局まで試す。
4. 結果を通過したノードへ戻し、最後は訪問回数が最大の根の手を選ぶ。

**評価・選択の式：** `選択: 確率0.2でランダム、それ以外は手番側の最大平均値`

**狙い：** 過去の試行を木として再利用する基本形を観察できます。

**限界：** UCTではありません。探索率は固定なので、予算や分岐数によっては配分が非効率です。

**比較の観点：** AI15と同じ木・プレイアウト・予算を用い、枝の選択規則の違いを比較できます。

**パラメータ：** 最大4,096ノード。終局まで完了しない試行はバックアップしません。

**実装：** `cpp/algorithms.hpp` の `mctsAI()`。

## AI07 — Greedy（1手評価）

1手だけ盤面を進め、共通の手作り評価関数が最も高くなる鏡を選びます。

### 動作手順

1. 全候補をシャッフルした順に試す。
2. 獲得コア差と、現在の光路から未獲得コアへの近さを計算する。
3. 最高評価の初手を返す。

**評価・選択の式：** `E(s) = コア差 × 100 + 光路の近さによる小さな補助点`

**狙い：** 軽量で解釈しやすく、深い探索なしの基準になります。

**限界：** 相手の次の獲得を明示的には調べません。コアへの近さは回転手数ではなく幾何的な近さです。

**比較の観点：** AI04・AI05の基準。AI25と比べると、手作り評価と学習評価の違いを見られます。

**パラメータ：** 通常は鏡の枚数と同じだけ遷移を試します。余った予算は無理に使い切りません。

**実装：** `cpp/algorithms.hpp` の `greedyAI()`。

## AI08 — Iterative Alpha-Beta（反復深化αβ）

深さ1、2、3…とαβ探索を繰り返し、最後に完了した深さの手を残します。

### 動作手順

1. 浅い探索で有効な代替手を得る。
2. 深さを1段ずつ増やす。
3. 予算が切れた時点で、途中の探索結果を捨てる。
4. 最後に根全体の探索が完了した手を採用する。

**評価・選択の式：** `採用する深さ = 全根候補を完了した最大の深さ`

**狙い：** 打ち切りがあっても、完了済みの読みを残せます。

**限界：** 反復深化は独立したゲーム戦略ではなく、αβ探索の実行方法です。浅い探索を繰り返す分の費用もあります。

**比較の観点：** AI05と比較して時間制約への適応を調べます。

**パラメータ：** 共通深さを最大深さとして利用。順序付けはAI05と揃えます。

**実装：** `cpp/algorithms.hpp` の `iterativeAI()`。

## AI09 — Beam + Rollout（選択探索＋試行）

上位k手の敵対的探索と、葉からのランダム対局を組み合わせます。

### 動作手順

1. 1手評価で各局面の候補を幅kに絞る。
2. 浅い枝を交互の最大化・最小化で探索する。
3. 葉から最大3回のランダム対局を行う。
4. 葉の推定得点を上へ戻して初手を決める。

**評価・選択の式：** `葉の値 ≈ 400 × (平均プレイアウト得点 − 0.5)`

**狙い：** 狭い戦術探索と、終局の結果を組み合わせられます。

**限界：** 候補削減の見落としと、試行回数の少なさによるノイズの両方を持ちます。予算で打ち切った試行は途中評価を用いることがあります。

**比較の観点：** AI04から葉の評価方法だけを変えた効果を調べます。

**パラメータ：** ビーム幅・最大深さ・共通予算。プレイアウトも同じ予算から消費します。

**実装：** `cpp/algorithms.hpp` の `hybridAI()`。

## AI10 — Genetic Planner（遺伝的計画）

自分の将来6回分の操作を遺伝子として持ち、選択・交叉・突然変異で改善します。

### 動作手順

1. 12個の行動列をランダム生成する。
2. 同一の乱数シナリオで、相手をランダムに動かして各列を評価する。
3. 2個体のトーナメント選択と一点交叉、各遺伝子20%の突然変異を行う。
4. 良い子を集団へ残し、最良列の最初の操作を実行する。

**評価・選択の式：** `適応度 = 終局の勝敗得点 + 0.01 × コア差`

**狙い：** 長い行動列の組み合わせを、木をすべて展開せず探索できます。

**限界：** 相手はランダムモデルです。1つの共通乱数シナリオへの過適合があり、固定行動列は実際の相手に崩されます。毎ターン再計画します。

**比較の観点：** AI11・AI12と同じ行動列表現・目的関数で、最適化手法を比較します。

**パラメータ：** 集団12、行動列長6、突然変異率20%。これらはC++の定数です。

**実装：** `cpp/algorithms.hpp` の `geneticAI()`。

## AI11 — Simulated Annealing（焼きなまし）

行動列の一部を変更し、初期は悪化する変更も受け入れて局所解からの脱出を狙います。

### 動作手順

1. 自分の6操作をランダム生成する。
2. 1か所を変更して終局を試す。
3. 改善は受け入れ、悪化も温度に応じた確率で受け入れる。
4. 温度を下げながら繰り返し、訪問した最良列の初手を使う。

**評価・選択の式：** `悪化を受け入れる確率 = exp((新評価 − 現評価) / T)`

**狙い：** 単純な山登りで抜けにくい局所解を探索できます。

**限界：** 相手の最善応手を保証しません。冷却方法、乱数シナリオ、予算への依存があります。

**比較の観点：** AI12と比較すると、悪化する変更を許すことの効果を測れます。

**パラメータ：** T = 0.35 / (1 + 0.035 × 反復回数)。目的関数と相手モデルはAI10と同じです。

**実装：** `cpp/algorithms.hpp` の `annealingAI()`。

## AI12 — Hill Climbing（再出発つき山登り）

行動列を1か所ずつ変え、評価が下がらない変更を残します。

### 動作手順

1. 6操作の行動列を用意する。
2. 1操作を書き換えて評価する。
3. 同等以上なら採用する。
4. 最良評価が24回更新されなければ再出発し、全体の最良列を保持する。

**評価・選択の式：** `新評価 ≥ 現評価 のとき更新`

**狙い：** 仕組みが明快で、焼きなましや遺伝的探索の基準になります。

**限界：** 局所解や評価の平坦な領域に弱く、相手モデルもランダムに固定されています。

**比較の観点：** AI10・AI11との比較に適しています。

**パラメータ：** 列長6、停滞24回でランダム再出発。毎ターン計画し直します。

**実装：** `cpp/algorithms.hpp` の `hillAI()`。

## AI13 — Expectimax（確率的な相手モデル）

自分は最善手を選び、相手は全合法手から均等に選ぶと仮定します。

### 動作手順

1. 自分の手番では評価を最大化する。
2. 相手の手番では全合法手の評価を平均する。
3. 深さを増やしながら、根全体を完了できた結果だけを残す。

**評価・選択の式：** `自分: max V(s′) ／ 相手: Σ V(s′) / 合法手数`

**狙い：** ランダムな相手に合わせた戦い方を研究できます。

**限界：** 確率ノードはこの決定論的ゲームの乱数ではなく、相手モデルです。強い敵への安全性を保証しません。

**比較の観点：** AI01相手とAI05相手で成績がどう変わるかを比較します。

**パラメータ：** 全幅の確率平均。部分的な平均を完全な期待値と扱わず、未完了なら浅い結果へ戻ります。

**実装：** `cpp/algorithms.hpp` の `expectimaxAI()`。

## AI14 — Plain Negamax（枝刈りなしNegamax）

ゼロサムのMinimaxを、手番が変わるたび評価の符号を反転する形で実装します。

### 動作手順

1. 現在の手番から評価する。
2. 子局面の評価に−1を掛ける。
3. その最大値を選ぶ。
4. 枝刈りせず、指定した深さを探索する。

**評価・選択の式：** `V(s) = maxₐ [ −V(next(s,a)) ]`

**狙い：** Minimaxとの関係を確認し、αβ枝刈りの検証用基準になります。

**限界：** Negamax自体が別の強い戦略というわけではありません。同じ深さ・評価関数ならMinimaxと同等で、分岐が大きいと遅くなります。

**比較の観点：** AI05と十分な予算で同じ結果になることをテストします。

**パラメータ：** 指定深さが未完了なら1手評価へ戻ります。

**実装：** `cpp/algorithms.hpp` の `negamaxAI()`。

## AI15 — UCT-MCTS（UCBによる木探索）

平均成績に「まだ十分試していない枝」へのボーナスを加えて、探索先を選びます。

### 動作手順

1. 未展開の手を順に展開する。
2. 手番側から見た平均値と探索ボーナスで子を選ぶ。
3. ランダムに終局まで進める。
4. 結果を木へ戻し、根で最も訪問した手を使う。

**評価・選択の式：** `UCB = Q + √2 × √(log(N親 + 1) / N子)`

**狙い：** 良さそうな枝の活用と、少数試行の枝の調査を両立します。

**限界：** 有限の計算予算で最善手を保証するものではありません。100〜200分岐では浅い試行に予算を使うことがあります。

**比較の観点：** AI06との差は枝の選択規則。AI16との差は展開する候補数です。

**パラメータ：** 探索定数√2、木の上限4,096ノード、ランダムプレイアウト。

**実装：** `cpp/algorithms.hpp` の `uctAI()`。

## AI16 — Progressive Widening（候補を徐々に拡大）

訪問数が少ない間は候補数を抑え、試行が増えると新しい手を展開します。

### 動作手順

1. 各ノードの許可候補数を訪問数から計算する。
2. 許可数未満なら新しい手を展開する。
3. それ以外はUCTで既存の手を選ぶ。
4. 通常のMCTSと同様に試行結果を戻す。

**評価・選択の式：** `許可候補数 = min(M, 2 + floor(1.7 × √(N + 1)))`

**狙い：** 鏡の枚数が多い場合に、少数の手を先に詳しく調べられます。

**限界：** 最初に選ばれなかった重要な手を調べるのが遅れます。強さが必ず上がるわけではありません。

**比較の観点：** AI15と鏡20・100・200枚を比較し、分岐数との関係を調べます。

**パラメータ：** 拡大係数1.7、指数0.5。候補順はシード付きでランダム化します。

**実装：** `cpp/algorithms.hpp` の `wideningAI()`。

## AI17 — Transposition Alpha-Beta（置換表つきαβ）

同じ局面に別の操作順から到達した際、以前の探索結果や境界を再利用します。

### 動作手順

1. 鏡の向き、手数、得点、コア所有者から局面キーを作る。
2. 一致する探索済み項目の深さと境界種別を確認する。
3. 正確値・下界・上界をαβ探索に利用する。
4. 完了した探索結果だけを置換表へ格納する。

**評価・選択の式：** `キー一致 + 十分な深さ → 評価値／探索境界を再利用`

**狙い：** 同じ鏡を2回回すと元に戻るゲームで、重複探索を減らせる可能性があります。

**限界：** 手番だけでなく残り手数が違えば同一局面ではありません。表の衝突では完全キーを照合し、対局や別の思考への誤流用を防ぎます。

**比較の観点：** AI08との比較に適しています。ただし根の評価順序付けも含むため、純粋な置換表だけの分離実験には設定の追加が必要です。

**パラメータ：** 8,192項目。1回の思考内で反復深化に再利用し、次の思考では世代を切り替えます。

**実装：** `cpp/algorithms.hpp` の `transpositionAI()`。

## AI18 — Threat Defense（反撃重視）

自分の操作後、相手が1手で作れる最悪の局面を重点的に調べます。

### 動作手順

1. 全初手を1手評価で並べる。
2. 各候補に対する相手の全合法手を調べる。
3. 相手が最善に応じた場合の評価をその初手の値にする。
4. 応手確認が完了した候補から最大値を選ぶ。

**評価・選択の式：** `初手の評価 = minᵦ E(next(next(s,a),b))`

**狙い：** 直後にコアを取られる操作を避ける戦術的な基準になります。

**限界：** 深い強制手順を証明するThreat-Space Searchではなく、明示的な2手戦術探索です。予算不足では一部の初手だけを調べます。

**比較の観点：** AI02の積極的な経路計画との攻防を比較できます。

**パラメータ：** 応手が未完了の候補は確定評価にしません。最低1手評価の代替手を持ちます。

**実装：** `cpp/algorithms.hpp` の `threatAI()`。

## AI19 — Laser-Aware Beam（光路を利用する探索）

現在の光路と、コアに届く経路候補の鏡を優先して、幅を絞った探索を行います。

### 動作手順

1. 光が通った鏡と、検証されたコア経路の鏡を抽出する。
2. 根の候補の評価順に、この知識の小さなボーナスを加える。
3. ビーム型Minimaxで先読みする。
4. 内部ノードでは光路外の準備手も1候補残す。

**評価・選択の式：** `候補順 = 共通評価 + 光路上の加点 + コア経路上の加点`

**狙い：** このゲーム固有の構造を使う独自の比較対象です。

**限界：** 現在の光路外の鏡が将来重要になるため、候補削減は安全な枝刈りではありません。BFSが一般最適性を証明するわけでもありません。

**比較の観点：** AI04との差を、鏡の枚数別に調べます。

**パラメータ：** ビーム幅・深さを共有。光路解析とBFSの訪問数も別途記録します。

**実装：** `cpp/algorithms.hpp` の `laserAwareAI()`。

## AI20 — Budgeted Ensemble（予算分割アンサンブル）

モンテカルロ・ビーム・反復深化αβに1つの予算を分け、投票で操作を決めます。

### 動作手順

1. 残りの計算予算を3方式へ順次配分する。
2. 各方式から1つずつ候補を受け取る。
3. 2方式以上で一致すればその手を選ぶ。
4. すべて異なれば反復深化αβの候補を採用する。

**評価・選択の式：** `1つの共通予算 → 3方式 → 多数決`

**狙い：** 異なる考え方の合意が有効かを調べられます。

**限界：** 各方式が単独のときより少ない予算しか得られません。多数決だから強い、という保証はありません。

**比較の観点：** AI03・AI04・AI08を単独で同じ全体予算に設定した成績と比べます。

**パラメータ：** 各方式に全予算を3重に与えません。時間予算も残りから分割します。

**実装：** `cpp/algorithms.hpp` の `ensembleAI()`。

## AI21 — Proof-Number Search（証明数探索）

「自分が最終的に勝てるか」を、OR/AND木の証明数・反証数で調べます。

### 動作手順

1. 未解決の葉を証明数1・反証数1で開始する。
2. 自分の節はOR、相手の節はANDとして必要な証明数を合成する。
3. 最も証明に近い葉を選び、全合法手を展開する。
4. 終局の勝敗だけを証明・反証に使い、資源不足なら未確定とする。

**評価・選択の式：** `OR: pn=min(pn子), dn=Σdn子 ／ AND: pn=Σpn子, dn=min(dn子)`

**狙い：** 局面の勝利を実際に証明できた場合と、単なる評価を区別できます。

**限界：** 引き分けは「厳密な勝利」の反証です。予算・木の容量不足なら未解決であり、必勝と表示しません。多分岐の序盤では未解決が普通です。

**比較の観点：** 終盤の小さな残り手数で、他方式との正確性を比較できます。

**パラメータ：** 最大4,096ノード。未完了の部分展開をAND節の完全な証明に使いません。

**実装：** `cpp/algorithms.hpp` の `proofAI()`。

## AI22 — Nested Rollout（入れ子の試行）

初手の先でも候補を試し、その評価に下位のランダム対局を使います。

### 動作手順

1. 根の初手を巡回する。
2. 相手側で幅kの候補をサンプリングする。
3. 各候補から終局までランダムに進める。
4. 相手に有利な結果を上位へ返し、初手ごとの平均を比較する。

**評価・選択の式：** `外側の試行 → 内側の候補比較 → ランダム対局`

**狙い：** 単純なランダム応手より、相手の選択を少し厳しく想定できます。

**限界：** 本実装は2人用に適応した深さ2のNested Rolloutです。原論文の単独プレイヤーNMCSや、論文中の全手続きをそのまま再現したものではありません。

**比較の観点：** AI03と同じ予算で、入れ子の比較に使う費用が有効かを調べます。

**パラメータ：** 内部のサンプル幅は共通ビーム幅。全ての相手応手を保証する方式ではありません。

**実装：** `cpp/algorithms.hpp` の `nestedAI()`。

## AI23 — RAVE-MCTS（後の手の情報も利用）

ある枝の直後だけでなく、その後の試行中に同じ手番側が使った操作の成績も共有します。

### 動作手順

1. 通常のUCTで木を探索し、試行中の操作列と手番を記録する。
2. 各祖先で、後に登場した同じ手番側の鏡操作へAMAF統計を加算する。
3. 直接の平均値とAMAF平均を混合する。
4. 試行が増えるにつれ、直接の情報を重視する。

**評価・選択の式：** `Q混合 = (1−β) × Q直接 + β × Q_AMAF`

**狙い：** 少ない試行から手の情報を共有する効果を検証できます。

**限界：** 鏡の回転は順序や偶奇が重要です。後で良かった手が今も良いとは限らず、囲碁での成果がこのゲームでも成り立つとは限りません。

**比較の観点：** AI15との直接比較で、共有が有利か有害かを測ります。

**パラメータ：** 同じ祖先・同じ手番側の同一操作は1試行で1回だけ加算。統計上限65,000。

**実装：** `cpp/algorithms.hpp` の `raveAI()`。

## AI24 — Heuristic PUCT（事前評価つき木探索）

光路上かどうかとコアへの幾何的距離から事前確率を作り、PUCTで探索を配分します。

### 動作手順

1. 各合法手に正の重みを与え、合計1へ正規化する。
2. 手番側の平均値に、事前確率で重み付けした探索ボーナスを加える。
3. 終局までのランダム対局で価値を更新する。
4. 根で訪問回数が最大の手を選ぶ。

**評価・選択の式：** `PUCT = Q + 1.5 × P(a) × √(N親+1) / (1+N子)`

**狙い：** ゲーム固有の弱い手掛かりを、木探索の配分に使えます。

**限界：** ニューラルネットワークは使いません。AlphaZeroそのものではなく、手作りの事前確率を用いる小規模なPUCT実験です。

**比較の観点：** AI15と比較し、事前評価の有効性を確認します。

**パラメータ：** 係数1.5、全手に正の事前確率。木とプレイアウトは他のMCTS系と共通です。

**実装：** `cpp/algorithms.hpp` の `puctAI()`。

## AI25 — Learned Linear Value（学習済み線形評価）

混合方策の自己対戦データから学習した、小さな線形評価関数で1手先を採点します。

### 動作手順

1. 学習用シードの600対局から、10個の局面特徴量と最終勝敗を記録する。
2. 対局単位・鏡枚数で偏らない分割を使い、リッジ回帰で重みを学習する。
3. 対戦時は各1手先を次の手番側の視点で予測し、符号を反転して自分側の評価に直す。
4. 終局では正確な勝敗評価を使い、それ以外は予測値の高い手を選ぶ。

**評価・選択の式：** `予測値 = w₀ + Σ wᵢ × 特徴量ᵢ`

**狙い：** 手作り評価と、実際にデータから得た評価を比較できます。学習スクリプトと重みを同梱します。

**限界：** 深層学習ではなく、10特徴の線形モデルです。弱い混合方策からのデータなので強さは未保証。対戦中に学習するわけではありません。

**比較の観点：** AI07との比較。学習データのシード1000000〜1000599は評価用に再利用しないでください。

**パラメータ：** 方策: 70% Random + 30% Greedy。モデル・データ・検証誤差はmodels/に保存。訓練費用は対局中の思考時間に含めません。

**実装：** `cpp/algorithms.hpp` の `learnedAI()`。
